# Karaoke / SPS Workbench — финальный рабочий цикл

Это финальная схема нового pipeline после Updates 001–013. Старые экспериментальные скрипты из исходного архива можно оставить для сравнения, но они больше не являются каноническим путём обработки.

## 1. Запуск

Обычный запуск из уже активированного Conda-окружения:

```bat
python run_gui.py
```

Либо на Windows через финальный launcher:

```bat
run_gui_conda.bat mfa
```

Имя окружения можно также задать переменной `KARAOKE_CONDA_ENV`.

Перед первой работой с проектом полезно выполнить:

```bat
python scripts\doctor.py C:\path\to\project
```

Диагностика проверяет Python/Tkinter, FFmpeg/ffplay, NumPy, структуру проекта, выбранное Conda-окружение, MFA и опциональные Sudachi-зависимости.

## 2. Project

Каждая песня должна жить в отдельном каталоге проекта:

- `source/` — исходные данные;
- `alignment/` — MFA/TextGrid;
- `subtitles/` — ASS;
- `cache/` — waveform, spectrogram, SPS sidecar;
- `exports/` — рендеры/экспорт;
- `project.json` — пути и настройки.

Это исключает старую проблему, когда `work/` содержал артефакты разных песен.

## 3. MFA / Alignment

Вкладка **Alignment** рассчитана на MFA в Conda. Указываются:

- Conda executable;
- имя окружения;
- `mfa` внутри окружения;
- HF или legacy model/dictionary;
- media и исходный transcript.

Перед запуском доступны Validate, OOV report и model list/download/inspect.

### Предобработка текста

Режимы:

1. **Без обработки** — исходный текст идёт в `.lab` как есть.
2. **Unicode + пробелы** — NFKC и нормализация пробелов.
3. **Japanese Sudachi** — токенизация SudachiPy внутри выбранного Conda-окружения, SplitMode A/B/C.

Удаление пунктуации опционально и по умолчанию выключено. Кнопка Preview показывает исходный и подготовленный текст до создания corpus. Исходный `.txt` никогда не перезаписывается; подготовленная версия сохраняется отдельно в `alignment/mfa/prepared_transcript.txt` и в `.lab`.

Для Japanese Sudachi нужны `sudachipy` и `sudachidict_core` в том же Conda environment, где работает MFA.

После выбора TXT флажок **Автоязык и модели** определяет один из поддерживаемых языков
(en/ru/de/pl/tr/hu/ja) и заполняет согласованную пару MFA dictionary + acoustic model.
Флажок можно выключить для ручного выбора языка и моделей. Для English legacy-пара —
`english_us_mfa` + `english_mfa`.

После MFA полученный TextGrid автоматически преобразуется в итоговый формат: слоги,
ровно один `Dialogue` на полный диапазон TextGrid, переносы внутри него через `\N` и
точное восстановление регистра/пунктуации из исходного TXT. Исходный TXT обязателен:
без него финальное преобразование не запускается. В ASS записывается `WrapStyle: 0`
для умного переноса. Используется исходный
стиль `Default`: `Heading Pro Variable`, 72 px, белый karaoke; красный цвет появляется
только от явных burst-тегов. Межстрочный render-spacing на этом этапе не применяется.
Паузы сохраняются timing-only тегами, не раздувают соседние слоги и не считаются
SPS-слогами.

## 4. Karaoke

Вкладка **Karaoke** использует waveform и отдельный overview timeline. Поддерживаются `\\k`, `\\kf`, `\\ko`, `\\K`.

Основные операции:

- перетаскивание границ;
- Insert;
- Split;
- Split по текстовому курсору;
- Merge;
- Delete с передачей длительности соседнему слогу;
- смена karaoke tag;
- редактирование текста;
- Undo/Redo;
- Save с `.bak`.

Viewport/zoom не должны сбрасываться после редактирования. Неизвестные ASS override-теги, включая цветовые burst-метки и `\\org/\\fr`, сохраняются.

## 5. SPS Measurement

Кнопка из Karaoke передаёт весь ASS или выделение в отдельную измерительную разметку. Перед передачей автоматически ищутся burst-кандидаты.

Karaoke timing и SPS timing независимы. Начало и конец каждого измеряемого слога можно подрезать отдельно; интервалы не обязаны соприкасаться. Изменённые вручную слоги визуально отличаются от исходных.

Есть:

- waveform;
- spectrogram;
- режим Both;
- voice-frequency presets;
- FFT/window/overlap/frequency/dB настройки;
- overview timeline с heat-кодированием скорости burst;
- ASS vs Measured SPS graph;
- точный SPS только методом legacy 1–2 s (`count / фактическая длительность`);
- strict fixed-window расчёты используются только внутри автоопределения кандидатов на бёрсты и не предлагаются как результат точного измерения;
- CSV export;
- sidecar `sps_measurements.json` вместо записи точных измерений обратно в ASS.

Транспорт поддерживает точки **In/Out** по слогам: их можно поставить вручную или взять из текущего выделения, затем воспроизводить ровно этот диапазон. После Stop или естественного окончания полоса по умолчанию возвращается к точке, откуда началось воспроизведение. Для текущего выделения SPS интерфейс показывает самое быстрое legacy-окно 1–2 s и позволяет выделить найденный бёрст. Кнопка **Окрасить бёрст** записывает в ASS `\c&Hff` перед первым выбранным слогом и bare `\c` сразу после последнего.

## 5.1 Настройки и горячие клавиши

`Настройки → Общие / Воспроизведение / Точный SPS / Горячие клавиши` объединяет пользовательские параметры. Настройки сохраняются глобально в UI preferences и переживают перезапуск. Горячие клавиши можно переназначать или отключать; конфликты с другими пользовательскими действиями и фиксированными `Ctrl+S`, Undo/Redo, F2 и `Ctrl+,` блокируются. По умолчанию Space — Play/Pause, Ctrl+Space — выделение, Shift+Space — In–Out, I/O ставят границы диапазона.

## 6. Render

Вкладка **Render** умеет:

- разбивать текст по максимальному числу слов;
- имитировать межстрочный интервал через далёкий `\\org` и микроповорот;
- измерять реальный bbox через FFmpeg/libass;
- автоматически crop-ать transparent karaoke overlay;
- дать ручной crop preview;
- экспортировать render-only ASS;
- создавать прозрачный MOV/qtrle или MP4;
- вжигать karaoke непосредственно в исходное видео с H.264/H.265 и Copy/AAC/No audio.

По умолчанию и standalone-overlay, и видео с вожжёнными субтитрами рендерятся с
масштабом разрешения `2×` по каждой стороне. Например, 1920×1080 превращается в
3840×2160; увеличение выполняется Lanczos до отрисовки субтитров libass. Масштаб
можно изменить в поле **Разрешение** вкладки Render.

Все layout-преобразования делаются в render-копии ASS; рабочий ASS не переписывается.

## 7. Legacy

`auto_language.py`, `textgrid_to_ass.py`, `hyphen_lang_as_arg.py`, `fix_subs.py` и
`fix_reg_punct_int.py` теперь являются переносимыми CLI-обёртками общего
`karaoke_core`: у них нет абсолютных путей предыдущей версии. GUI использует те же
функции ядра напрямую, без запуска цепочки дочерних Python-процессов.

Остальные старые SPS regex-скрипты и ручные MFA batch-файлы не нужно смешивать с
новым pipeline.

## 8. Минимальные зависимости

Приложение: Python + Tkinter + portable FFmpeg. NumPy нужен для спектрограммы и быстрого PCM-транспорта, `sounddevice`/PortAudio — для низколатентного Audacity-like воспроизведения.

В Conda-среде рекомендуется установить `python-sounddevice` из conda-forge (либо `python -m pip install sounddevice`). MFA работает из выбранного Conda environment. Sudachi — только для опциональной японской предобработки.

См. `environment.example.yml`, `requirements.txt` и `scripts/doctor.py`.

## Низколатентное воспроизведение (Update 027)

Транспорт теперь устроен ближе к Audacity: после привязки медиа FFmpeg **один раз** создаёт seekable PCM-кэш 48 kHz/stereo, а затем нажатия Play/Space больше не запускают FFmpeg и не открывают аудиоустройство заново. PortAudio (`sounddevice`) держит один output stream открытым постоянно.

- `Space` — глобальный Play/Pause, кроме настоящих текстовых полей, где пробел остаётся пробелом. Клик по таймлайну переводит клавиатурный фокус на него.
- `▶/⏸` — обычное воспроизведение от текущего курсора до конца файла.
- `▶ Слог` / `▶ Выделение` — тот же постоянный stream с конечной границей, поэтому очень короткий слог не должен терять начало/конец из-за старта отдельного плеера.
- PCM-кэш строится один раз и хранится в `cache/playback/`; после этого seek выполняется чтением готовых сэмплов.
- При 1× звук всегда идёт прямо из PCM-кэша.
- При другой скорости можно переключать `Сохранять тон`:
  - выключено — скорость и pitch меняются вместе, ресэмплинг выполняется внутри процесса без запуска FFmpeg;
  - включено — PortAudio остаётся открытым, а FFmpeg `atempo` используется только как фоновый time-stretch процесс над уже декодированным PCM-кэшем.
- Полоса воспроизведения вычисляется по реально отправленным PortAudio-фреймам. Заявленная драйвером output latency не вычитается; ручная коррекция остаётся только для тонкой подстройки.
- Старые warm-up/tail и winsound/ffplay остаются только историческим fallback и не используются при рабочем PortAudio backend.

## Update 029 — синхронизация playhead

PortAudio-плеер больше не задерживает полосу на заявленную драйвером `stream.latency` и не наследует старую обязательную 80-мс visual delay. Playhead следует за PCM-фреймами, переданными постоянному PortAudio stream, с первого callback-блока.

В `Точный SPS -> Настройки прослушивания` осталась только тонкая **коррекция полосы** от -250 до +250 мс. 0 мс — рекомендуемое значение. Отрицательное значение сдвигает полосу назад, положительное — вперёд. Старый параметр `playback_cursor_delay_ms` при миграции игнорируется и становится 0 мс.


## Update 031 — смена системного аудиоустройства

PortAudio stream больше не считается навсегда привязанным к устройству, которое было default при запуске программы. На Windows транспорт отслеживает текущий Core Audio default render endpoint. Если пользователь переключает вывод (например, динамики → Bluetooth-наушники/HDMI/USB DAC), старый stream закрывается, PortAudio обновляет каталог устройств и stream переоткрывается на новом WASAPI default.

По умолчанию включено `Настройки → Воспроизведение → Следовать системному устройству вывода по умолчанию`. Там же есть кнопка `Переподключить сейчас` и отображается фактически открытый PortAudio/WASAPI device. Переоткрытие выполняется только при реальной смене endpoint, поэтому обычные Play/Space не получают дополнительного старта аудиоустройства.

## Update 032 — независимые границы обычного Play

Обычный `Space`/`▶` и диапазон `In–Out` теперь независимы. `Старт от` привязывает начало каждого нового обычного Play к началу выбранного слога, `Стоп после` ограничивает конец концом выбранного слога. Любая граница может использоваться отдельно; без `Старт от` воспроизведение начинается ровно с текущей полосы, без `Стоп после` идёт до конца медиа. `×S`/`×E` очищают их независимо. `In/Out` остаётся отдельным способом воспроизведения фиксированного диапазона.

Если обе обычные границы заданы и образуют корректный сегмент, рядом показывается самый быстрый бёрст только по точному пользовательскому методу Legacy 1–2 s. В Precise SPS используются effective/measurement-границы слогов.

Возврат playhead после Stop/естественного окончания теперь использует неизменяемую точку старта пользовательской команды Play и не сбрасывается внутренними рестартами PortAudio. Скорости от `0.97×` до `1.03×` включительно нормализуются к `1.00×` во всём playback pipeline и при сохранении настроек.

## Update 033 — единые маркеры транспорта и разметка пустого ASS

Начиная с Update 033 прежние отдельные `Старт от` / `Стоп после` и In/Out
заменены одной парой маркеров, общей для вкладок **Караоке** и **Точный SPS**.
`|←` ставит начало, `→|` — конец, `|▶` играет от начала дальше, `▶|` играет от
текущей полосы до конца-маркера, а `|▶|` играет ровно между двумя маркерами.
`↔` ставит обе границы по выделению. Обычный Space не использует эти маркеры;
если им прервать специальное ограниченное воспроизведение, спецрежим
сбрасывается и следующий Space продолжает обычный транспорт от текущей точки.

При включённой настройке возврата playhead ручной Stop и естественное окончание
возвращают полосу к старту конкретной пользовательской команды воспроизведения.
После Stop дополнительно выполняется один защищённый `after_idle`-возврат,
который не позволяет последнему уже поставленному в очередь кадру playhead
снова увести полосу вперёд.

Названия основных вкладок больше не содержат номера: **Подготовка**, **Караоке**,
**Точный SPS**, **Рендер**, **Логи**.

Для разметки песни без известного текста можно создать **Новый пустой ASS**.
Такой документ содержит один невидимый пустой karaoke timing-span на всю
известную длительность медиа; это техническая заготовка, которую можно сразу
резать курсором на нужные слоги и затем сохранить как обычный ASS.

GUI-команды Split и Insert теперь делят **время в позиции полосы
воспроизведения**, а не пополам. Обычный Split делит видимый текст
пропорционально получившимся длительностям. ASS override-блоки `{...}` не
считаются символами и не разрезаются; `\\N`/`\\n`/`\\h` считаются одним
видимым элементом, комбинированные Unicode/ZWJ-кластеры сохраняются целиком.
Пустой текст разрешён. Split по текстовому курсору оставляет текстовую границу
в позиции caret, но временную границу берёт с playback playhead.

Для истории документа закреплены `Ctrl+Z` (Undo), `Ctrl+Shift+Z` и `Ctrl+Y`
(Redo). В настоящих полях ввода эти сочетания оставлены локальному редактору
текста, а на остальных элементах интерфейса управляют историей ASS.
